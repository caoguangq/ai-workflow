# Spring Boot 后端规范（栈规范，可选启用）

> 本文件只写本栈特有的可执行契约。通用规则见 `generic/`。构建、测试、静态检查命令一律由 `profile.commands` 提供，本文件不写命令。

## 分层职责

1. Controller 只做三件事：参数校验、调用 Service、构造响应。不得包含业务分支。
2. Service 承担业务规则与事务边界。跨 Service 调用通过接口，不直接依赖实现类。
3. Mapper / Repository 不得包含业务规则，只做数据访问与必要的查询组装。
4. 实体（Entity）不得直接作为对外响应体；对外结构单独定义，避免持久化模型与契约耦合。

## 事务边界

1. `@Transactional` 只加在 Service 的公开方法上，不加在 Controller 或 Mapper 上。
2. 默认只读事务用于查询方法。
3. 事务方法内不得调用外部网络服务；确需调用时须说明超时与失败后的一致性处理。
4. 捕获异常后若吞掉，必须显式确认事务不会被标记为回滚。

## 状态与并发

1. 状态迁移集中在 Service，且每条迁移都应有对应的守卫条件。
2. 涉及状态迁移的写操作必须考虑重复提交：幂等键或状态前置校验。
3. 乐观锁字段变更必须与业务状态变更在同一事务内。

## 异常与响应

1. 业务异常使用统一的业务异常类型，携带稳定错误码。
2. 全局异常处理器是唯一的响应格式出口，Controller 内不得自行拼装错误响应。
3. 参数校验失败与业务规则失败必须可区分。

## 质量检查

- [ ] 新增接口是否声明了失败模式与错误码。
- [ ] 状态迁移是否都有前置守卫，且守卫失败有明确响应。
- [ ] 事务注解位置是否正确。
- [ ] 对外结构是否与实体解耦。
