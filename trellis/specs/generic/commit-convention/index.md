# 提交规范

## 开发前检查清单

- [ ] 已确认本次提交只包含一个逻辑变更。
- [ ] 已确认提交信息描述的是「为什么」和「影响」，不是逐行复述代码。

## 可执行契约

1. **格式**：`<type>: <描述>`，描述用中文，不超过 50 字。
2. **type 取值**：`feat` / `fix` / `refactor` / `test` / `docs` / `chore` / `perf`。
3. **一次提交一个逻辑变更**：功能改动与其格式化、重命名、无关修复分开提交。
4. **修复类提交必须写清触发条件**：什么输入或状态下会出错。
5. **必须可回滚**：单次提交不应把「需要同时回滚的另一半」留在别处。
6. **不得提交的内容**：本地环境文件、密钥、构建产物、调试用打印、被注释掉的代码块。

## 质量检查

- [ ] `git status --porcelain` 是否只包含本次意图内的文件。
- [ ] 提交信息能否让半年后的自己看懂为什么改。
- [ ] 是否混入了无关的格式化或重排。
