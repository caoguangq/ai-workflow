# 测试策略

## 开发前检查清单

- [ ] 已确认本次改动属于哪一类：纯逻辑 / 边界契约 / 集成行为 / 仅配置。
- [ ] 已确认项目现有的测试分层与命名约定。
- [ ] 已确认哪些行为由现有测试覆盖，避免重复。

## 可执行契约

1. **测试断言行为，不断言实现**：断言对外可观察的结果，不断言内部调用次数（除非该调用本身就是契约）。
2. **每条测试只验证一个行为**，测试名描述行为而非方法名。
3. **失败信息必须能定位**：断言需带上下文（输入、期望、实际）。
4. **测试必须可独立运行**：不依赖执行顺序、不依赖共享可变状态、不依赖外部服务的真实可用性。
5. **回归测试必须绑定缺陷**：修复缺陷时补的测试，需在注释中写明对应的缺陷场景。
6. **领域规则优先于覆盖率**：优先为 `spec/` 中描述的规则写测试，其次才看覆盖率数字。
7. **允许显式不测**：无法稳定测试的部分，写一条标注「不测原因 + 人工验证方式」的说明，而不是写一个永远通过的测试。

## 质量检查

- [ ] 新增测试在删除对应实现后是否会失败（反证有效性）。
- [ ] 是否存在依赖时间、随机数或执行顺序而不受控的测试。
- [ ] 测试名能否让失败报告自解释。
- [ ] 是否有被跳过的测试没有说明原因。
