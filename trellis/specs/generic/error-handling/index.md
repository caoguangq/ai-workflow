# 错误处理

## 开发前检查清单

- [ ] 已确认本次改动涉及的错误分类：用户输入错误 / 依赖失败 / 内部不变量破坏 / 并发冲突。
- [ ] 已确认现有代码中同类错误的处理方式，并与之一致。
- [ ] 已确认错误是否会跨越进程或网络边界（序列化后语义是否保持）。

## 可执行契约

1. **每个对外入口必须声明失败模式**：可能抛出的错误类型、触发条件、返回给调用方的形态。
2. **错误必须携带定位信息**：至少包含一个可检索的稳定标识（错误码或枚举名），不得只靠消息文本区分。
3. **不得吞掉错误**：捕获后要么处理、要么包装后重新抛出、要么显式记录并说明为何可以继续。
4. **用户可见错误与内部错误分离**：面向用户的文案不得泄露内部结构、表名、堆栈。
5. **重试必须有上限与退避**，且只对幂等操作重试。
6. **资源型错误（超时、连接中断）必须区分于业务型错误**，前者不得进入业务分支。

## 质量检查

- [ ] 新增的失败路径是否有对应测试或显式的「不测」理由。
- [ ] 错误消息中是否含可检索标识。
- [ ] 是否存在 `catch` 后无任何动作的空分支。
- [ ] 跨边界传递的错误是否在两端都有定义。
