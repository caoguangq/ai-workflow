# 日志

## 开发前检查清单

- [ ] 已确认本次改动运行在哪个进程/服务，日志应落到哪里。
- [ ] 已确认相关代码中已有的日志字段命名约定。

## 可执行契约

1. **每条日志必须能回答三个问题**：发生了什么、针对哪个对象、在哪个环节。
2. **结构化字段优先于拼接字符串**：可检索的键值对优于自然语言句子。
3. **级别语义固定**：
   - `ERROR` —— 需要人工介入的失败。
   - `WARN` —— 自动恢复但值得关注的异常。
   - `INFO` —— 状态迁移与关键决策。
   - `DEBUG` —— 仅开发排查使用，不得记录在默认级别。
4. **禁止记录敏感数据**：凭据、令牌、完整证件号、完整手机号、密码哈希。
5. **同一异常不得在多层重复记录**：在能处理或能附加信息的那一层记录，其余层透传。
6. **循环体内不得无界记录**：批量操作只记录汇总与抽样。

## 质量检查

- [ ] 新增日志是否带可检索标识（用户/任务/请求标识）。
- [ ] 是否存在把异常对象转成字符串后丢失堆栈的写法。
- [ ] 是否有日志在热路径上造成明显开销。
